# Aurora v0.3.0 规划 — NPM 全局包更新检查

> 状态：规划中（分支 `feat/v0.3.0`）
> 目标：新增第三个视图「NPM 全局包」，自动发现 `npm root -g` 下的全局包，逐包对比 npm registry 的 `latest` 版本并标记可更新项。

## 1. 背景与目标

Aurora 目前监控两类对象：GitHub/HTML 来源的桌面软件（软件雷达）与 VSCode 离线 .vsix 备份。全局 npm 包（CLI 工具等）升级目前靠手动 `npm outdated -g` / `npm i -g`，不在任何视图里。

v0.3.0 目标：

- 自动定位全局 node_modules（执行 `npm root -g`；支持设置里手动指定目录兜底）。
- 扫描其下直系包（含 `@scope/name`）的 `package.json` 得到本地版本清单。
- 逐包查询 registry 的 `dist-tags.latest`，复用现有版本比较语义标记「可更新」。
- 结果持久化到配置（同 `vscodeChecks` 模式），重启/切视图可恢复。
- 提供低成本升级动作：复制 `npm install -g <name>@latest` 命令。

## 2. 非目标（本版不做）

- ~~不做应用内一键升级~~（开发中按需求追加：已实现「执行更新」，应用内串行执行 `npm install -g <name>@latest`，进度经 `npm-upgrade-progress` 事件实时展示、可取消，完成后回填版本）
- 不做包的安装/卸载管理、项目级 `node_modules` 检查、lockfile 分析。
- 不解析 `package-lock.json`，本地版本一律以各包 `package.json` 的 `name`/`version` 为准（天然规避 npm 别名包 `npm:xxx` 的显示歧义）。
- 不做逐条检查进度（对齐 VSCode 页的批量一把梭模式）。

## 3. 交互设计

- 顶栏视图切换由两段改三段：`软件雷达 / VSCode 插件 / NPM 全局包`（`view: "radar" | "vscode" | "npm"`）。顶栏「扫描 / 检查全部」按钮与状态栏计数按现有 else-if 链扩展第三分支。
- 新组件 `src/components/NpmPanel.vue`，完全照抄 `VscodePanel.vue` 的面板模式：
  - `v-show` 常驻 + `defineExpose({ scan, check, busy })` 供顶栏直调；
  - props：`settings`、`initialChecks`；事件：`notify` / `persist`（如需）/ `stats` / `saveChecks`；
  - `watch(() => props.settings.npmGlobalRoot, …, { immediate: true })` 目录变化自动重扫。
- 行布局（沿用 `.vrow` 体系）：包名 + 状态 pill（未检查/可更新/已最新/检查失败）｜本地版本｜最新版本（title 显示「x 分钟前检查」）｜操作：**复制升级命令**、**打开 npm 页面**。
  - 复制命令走 `navigator.clipboard.writeText`（点击处理器内调用，WebView2 允许），成功 toast「已复制」，避免为此新增剪贴板插件。
  - 打开页面：`https://www.npmjs.com/package/<name>`（scoped 包 `<name>` 用 `@scope%2Fname`），走现有 `open_url`。
- 空态三种：未检测到 npm（提示安装 Node.js 或去设置手动填目录）、全局目录下没有包、npm 命令执行失败。
- 设置面板（`SettingsPanel.vue`）新增两项：
  - **npm 全局目录**（`npmGlobalRoot`）：留空 = 自动执行 `npm root -g`；填写 = 直接扫描该目录（GUI 环境 PATH 异常时的兜底，与 `vscodeDir` 手填模式一致）。
  - **npm Registry**（`npmRegistry`）：默认 `https://registry.npmjs.org`，国内可切 `https://registry.npmmirror.com`（镜像 registry 的路径与官方兼容，含 `/-/package/<name>/dist-tags`）。

## 4. 数据模型（Rust `model.rs` ⇄ `src/types.ts` 双侧同步）

沿用 `camelCase` 映射约定，新类型与 `VsixInfo/VsixRef/VsixCheck` 一一对应：

| Rust（model.rs） | TS（types.ts） | 说明 |
|---|---|---|
| `NpmInfo { name, version, dir }` | `NpmInfo` | 扫描结果；`dir` 为包目录绝对路径（定位/排查用） |
| `NpmRef { name, local_version }` | `NpmRef { name, localVersion }` | 参与检查的最小集合 |
| `NpmCheck { name, local_version, latest_version, has_update, checked_at, error }` | `NpmCheck` | 检查结果；`checked_at` 由前端填写（epoch 毫秒）；无下载直链字段 |

- `Settings` 增加：`npm_global_root: String`（默认空）、`npm_registry: String`（默认 `https://registry.npmjs.org`），均 `#[serde(default)]` 保证旧配置兼容；`types.ts` 的 `Settings` 同步。
- `Config` 增加 `npm_checks: Vec<NpmCheck>`（结构体级 `default` 已兜底）；**注意 `seed_config()` 是字面量构造，必须同步补字段**。
- 版本比较复用 `version::compare` / `compareVersion`（两份实现本就要求同步，无新逻辑）。

## 5. 后端设计：新模块 `src-tauri/src/npm.rs`

模式对标 `vscode.rs`，注册进 `lib.rs` 的 `generate_handler!`。

### 5.1 命令

```rust
/// 解析全局目录：settings.npm_global_root 非空且为目录 → 直接返回；
/// 否则执行 `npm root -g`，取 stdout trim()。失败返回 Err（前端转空态）。
#[tauri::command]
pub async fn npm_detect_root(manual: String) -> Result<String, String>

/// 扫描 <root> 下直系子目录（及 @scope 一层）的 package.json，
/// 读 name/version；目录不存在返回空表。async 放工作线程，模式同 list_vsix。
#[tauri::command]
pub async fn scan_npm(root: String) -> Result<Vec<NpmInfo>, String>

/// 逐包查询 registry，限并发（tokio Semaphore，6 路），
/// 返回与入参同序的 Vec<NpmCheck>。
#[tauri::command]
pub async fn check_npm_updates(items: Vec<NpmRef>, settings: Settings) -> Result<Vec<NpmCheck>, String>
```

### 5.2 扫描规则（`npm root -g` 指向 `<prefix>/node_modules`）

- 只看**直系子目录**：有 `package.json` 即收录（名字、版本以文件内容为准，不靠目录名解析）。
- 子目录以 `@` 开头视为 scope，进入其下一层继续找 `package.json`（`@types/node` 等）。
- 跳过：以 `.` 开头（`.bin`、`.package-lock.json`）、以 `_` 开头（`_npx`、`_cacache`）、无 `package.json` 或 JSON 解析失败或 `name`/`version` 缺失的目录。
- 结果按 `name` 排序；`name` 保留 scope 原文（`@types/node`）。

### 5.3 registry 检查

- 端点：`GET {npmRegistry}/-/package/{name}/dist-tags`（响应仅 `{"latest":"x.y.z",…}`，比完整 packument 小几个数量级；npmmirror 兼容此路径）。scoped 包名 URL 编码为 `@scope%2Fname`。
- **不**走完整 packument；若后续发现个别镜像不支持 dist-tags 端点，回退方案是 packument + `Accept: application/vnd.npm.install-v1+json`（abbreviated 元数据，同样含 dist-tags）。
- 客户端复用 `net::client_with_ipv4_pref(host)` —— registry 域名同样存在国内 IPv6 半通问题，按 AGENTS 约定统一走 IPv4 优先。
- `has_update = compare(latest, local) == Greater`，语义与 `check_vscode_updates` 完全一致。
- 单包失败只写该包的 `error`（如「registry 未收录」「请求失败：超时」），不中断整批。

### 5.4 Windows 执行 `npm root -g` 的细节

- GUI 进程下 `Command::new("npm")` 会因 `npm.cmd` 而失败：Windows 分支用 `cmd /C npm root -g`，并加 `CREATE_NO_WINDOW`（`std::os::windows::process::CommandExt`）避免控制台窗口闪烁；非 Windows 直接 `npm root -g`。
- 命令失败 / stdout 为空 → `Err("未检测到 npm…")`，由前端映射到「未检测到 npm」空态 + 引导设置手动目录。
- 打包版从资源管理器启动时 PATH 与终端可能不同：这就是保留 `npmGlobalRoot` 手动兜底的原因，文案里要写明。

- `src/api.ts`：`npmDetectRoot(manual)` / `scanNpm(root)` / `checkNpmUpdates(items, settings)` 三个方法，**每个都同时写 Tauri 与 mock 分支**（AGENTS 硬性要求，保证 `npm run dev` 可用）。
- `src/mock.ts`：`mockNpmRoot`（返回一个含 5~6 个包的模拟目录）、`mockScanNpm`（含 scope 包与一个「有更新」样本）、`mockNpmChecks`（多数最新、一两个可更新、一个 error 样本，对齐 `mockVscodeChecks` 的风格）。

- `src/App.vue`：`view` 联合类型加 `"npm"`；`npmPanel` ref + `npmStats`；顶栏 seg 三段、扫描/检查按钮与状态栏各加第三分支；`saveNpmChecks` 写 `config.npmChecks` 后 `persist()`（模式同 `saveVscodeChecks`）。

## 8. 风险与已知坑（提前列）

1. **Windows spawn npm**：必须 `cmd /C` + `CREATE_NO_WINDOW`；PATH 缺失时有手动目录兜底（§5.4）。
2. **registry 网络**：IPv4 优先客户端必用；提供 npmmirror 切换。
3. **packument 体积**：坚持 dist-tags 端点，避免全量元数据（大包可达数 MB）。
4. **scoped 包编码**：URL 里 `@scope/name` → `@scope%2Fname`，npm 页链接同理。
5. **nvm-windows / 自定义 prefix**：`npm root -g` 返回值随 prefix 变化，方案天然兼容（每次点扫描都重新探测，不缓存路径）。
6. **vue-tsc 3.3 内联处理器推断**：App.vue 里给 NpmPanel 事件的箭头函数参数写显式类型（已知坑，如 `@stats="(t: number, u: number) => …"`）。
7. **vite HMR 状态残留**：改 `<script setup>` 结构后整重启 dev server（已知坑）。
